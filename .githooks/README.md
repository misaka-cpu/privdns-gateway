# 提交前快速门

```bash
git config core.hooksPath .githooks
```

**每份克隆各做一次**（git 不会自动启用仓库里的钩子，这是它的安全设计）。

## 这里放什么

只放**又快又常犯**的那几条，目的是把反馈落在**写的当下**。

目前一条：救援端口/路径的单一事实源（`tests/test-rescue-constants.sh`，0.1 秒量级）。
这条不变量在本仓库被违反过**五次**，每次形态一模一样 —— 新写一支测试时顺手敲了端口。
守卫一直都在，但它只在全量回归里跑到：从敲下数字到 CI 判红隔着约半小时一整轮往返，
那时人早就在做别的事了。规矩写在文档里、也确实读过，照样会犯 ——
所以这不是记性问题，是**反馈延迟**问题。

## 这里不放什么

**不替代 CI。** CI 里那些步骤照旧全跑。别人的克隆、没装钩子的环境、以及被 `--no-verify`
绕过的提交，都还得靠 CI 兜住。这道门只负责把最常犯的那条提前。

加新门的标准：

- 单条 < 1 秒；
- 判据已有单一事实源 —— **直接调它**，不在钩子里抄一份逻辑（抄第二份迟早漂移，
  这是本仓库反复吃过亏的地方）；
- 是"写的当下就该知道"的那种错。

慢的、需要容器或 root 的，一律留给 CI。

## 绕过

用 git 自带的 `git commit --no-verify`，这里不另造开关。绕过之后 CI 仍会拦。
