# v1.11.15 旧 CLI 预修补: 升级到 v1.11.16 之前(可选)

v1.11.15 的 `/usr/local/bin/pdg` 执行普通 `pdg update` 时, 走的是**它自己**的升级与回滚代码。
v1.11.16 修掉的两处问题, 在这一跳上仍由旧代码决定:

- WLOC 已关闭、pdg-mitm 已停止(A-off)时, 升级可能把 pdg-mitm 重新拉起;
- 升级失败自动回滚时, 新增的 pdg-dotwitness unit 与开机自启链接不会被撤除。

本目录提供针对这两处的修补件。是否采用、在什么维护条件下替换, 由操作者另行确认; 未修补时的限制见文末。

下文用 **P0** 指 v1.11.15 原样状态, **P1** 指 P0 上只把 `/usr/local/bin/pdg` 换成修补件后的状态。

## 人工操作检查清单

本文不提供可直接执行的安装脚本。每一项都要实际读出结果并记录; 任何一项不成立就停止。

1. **取得修补件**: 从可信来源取得修补件, 核对完整 SHA256 等于 `fbb4ff80…`(上表全长值)。不符就停止。
2. **核对现状**: 核对 `/usr/local/bin/pdg` 的摘要、`/opt/privdns-gateway` 的 HEAD 与树、跟踪文件是否干净,
   逐项与"适用范围"一致。读取失败、命令报错或输出为空, 都不能当成状态正常, 一律停止。
3. **保存原件**: 替换之前, 把原件连同权限、属主、大小与修改时间等元数据另存到只有 root 可读的位置;
   回读备份, 确认其摘要与原件一致。不一致就停止。
4. **替换并独立核对**: 只在另行确认的维护条件下执行(例如维护窗口与可用的恢复通道)。替换对象只有
   `/usr/local/bin/pdg`(权限 755、属主 root)。完成后独立核对实际摘要等于 `fbb4ff80…`, 以及权限与属主。
5. **核对失败的含义**: 替换之后的核对失败, 可能意味着文件已经改变; 不能假定"失败即零改动"。
   先确认现状, 再决定是否用第 3 步的备份恢复。
6. **升级之后**: 运行普通 `pdg update` 之后, 只恢复一个 CLI 文件不等于整套产品回退。
7. **回滚的预期**: P1 升级到 v1.11.16 失败时, 自动回滚由修补件执行, 预期恢复到 P1(修补件), 不是 P0 的原件;
   实际身份仍须核验, 不预设为必然成功。

## 修补后的支持边界

- 修补件**不是**完整的 v1.11.16。它带有 A-off 停止态保留与"新增服务原先不存在"的恢复, 但没有
  v1.11.16 的 S-2 防火墙回滚记录: 它的 `cmd_rollback` 仍以 `_nft_apply_main >/dev/null 2>&1 || true`
  重载主防火墙, 加载失败不会计入回滚结果。
- 修补件的快照收录 `/usr/local/bin/pdg`, 所以用它回滚的预期目标是 P1, 不是逐字节的 P0。
- 改动针对升级期间的相关路径; 验证仅覆盖已有登记场景, 开机路径未验证。
- "未验证"不等于验证失败, 也不表示相应的生产风险已被接受。

## 未修补时的限制

- v1.11.15 原件的普通 update: A-off 时按原版控制流仍可能尝试重启 pdg-mitm;
- 它的自动回滚不含"新增服务原先不存在"的恢复;
- "未修补的 v1.11.15 → v1.11.16"这条升级路线未验证。
