# 救援平面 · 手机端访问与指纹核对

救援平面用自签证书，浏览器一定会警告。这份文档讲的就是那个警告该怎么处理 —— 不是"点忽略"，
而是先确认对面确实是你的网关。

## 为什么必须核对指纹

自签证书只保证这条连接被加密，**不保证对面是谁**。公网 CA 那套信任链在这里不存在，所以浏览器
的地址栏、锁形图标、"继续访问"按钮都给不出任何身份结论。

能区分"我的网关"和"别人"的只有证书指纹，而且指纹必须**从另一条路拿到**：

```bash
ssh <你的网关> sudo pdg rescue fingerprint
```

安装时抄下来存好也行。

**页面上显示的指纹不能用来核对页面自己。** 中间人既然能伪造页面，也就能把页面上那串指纹一起
改成他自己证书的指纹 —— 两边都是他给的，对上了什么也说明不了。指纹的价值全部来自"它是从
另一条独立路径拿到的"。

## 核对顺序（两个平台一样）

1. 先从 SSH 取指纹，或翻出安装时存的那一份。
2. 用浏览器打开 `https://<bind 地址>:8446/`。
3. 出现证书警告 → 进入证书详情，找到 **SHA-256 指纹**。
4. 与第 1 步拿到的逐字符比对。**对不上就停在这里**，不要继续，不要输 token。
5. 完全一致，再输入 token 登录。

指纹是 32 字节、64 个十六进制字符。比对时至少核对开头和结尾各若干组，不要只看前两组 —— 前缀
碰撞比整串碰撞容易得多。

## iOS

Safari 遇到自签证书会拦一道，页面上有查看证书详情的入口（不同 iOS 版本上这个入口的名字和位置
不一样，这里不写死按钮名；找"证书详情""显示详细信息"一类的入口）。

- 证书详情里能翻到 SHA-256 指纹时：照上面的顺序比对，一致再登录。
- **翻不到完整 SHA-256 指纹时**：不要输 token。iOS 上的证书查看器在部分版本里只给出摘要信息
  或只显示 SHA-1。这种情况下换一条路：
  - 用电脑浏览器访问同一个地址核对指纹（要求电脑也在允许的来源网段里），或
  - 直接用 SSH 处理问题 —— 救援平面能做的事，SSH 上都能做，它存在的意义是"SSH 不方便时还有
    一条路"，不是"必须用它"。

把证书装进"信任的证书"里可以免掉每次警告，但那等于把这张自签证书提升成一个可信根，代价是
它以后能给任何域名签证书。除非你清楚这个取舍，否则不建议这么做；`rotate cert` 之后还得再来
一遍。

## Android

**[SKIP：本轮没有真实 Android 设备可用，未做实测。]**

以下只写与浏览器无关、可以从协议本身确认的部分：核对顺序与 iOS 一致（取指纹 → 打开页面 →
进证书详情 → 比对 SHA-256 → 一致才输 token）。Android 上不同浏览器对自签证书的处理差异较大，
有的能看到完整指纹、有的不能。**看不到完整 SHA-256 指纹时，一律不要输 token**，改用电脑或 SSH。

不要为了让某个浏览器不再警告，把这张证书装进系统或用户证书库 —— 理由与 iOS 那段相同。

## 轮换之后

| 操作 | 证书指纹 | 已登录会话 | 你要做什么 |
|---|---|---|---|
| `pdg rescue rotate token` | 不变 | 立即全部失效 | 用新 token 重新登录；指纹不用重新核对 |
| `pdg rescue rotate cert` | **一定改变** | 服务重启，需要重新登录 | 重新从 SSH 取指纹再核对，然后登录 |

`rotate cert` 之后浏览器会再次警告、而且会提示证书与上次不同 —— 那是预期的。但"预期的变化"和
"被中间人换了证书"在浏览器看来长得一模一样，所以**必须**重新走一次独立取指纹的流程，不能因为
"我刚刚轮换过"就直接点过去。

## 端口能连上 ≠ 对面是你的机器

监听地址是公网可路由地址时，端口访问受两层限制：

- nft 只放行来自内网卡来源段的连接；
- 服务本身按内核给出的对端地址再判一次，TLS 握手之前就拒（不读 `X-Forwarded-For`，那是客户端
  可以随便写的）。

这两层管的是"谁能连上来"。它们不替代指纹核对 —— 指纹回答的是另一个问题："这台机器是不是我的"。

## 一点操作习惯

- token 和指纹不要放进同一条聊天记录、同一张截图、同一个笔记条目。拿到其中之一的人不该顺手
  拿到另一个。
- 救援页面的截图里可能带着 token 输入框、事务 ID、快照 ID，转发前先想清楚。
- 长期不用就 `pdg rescue disable`；需要时再开，端口不必一直挂着。
